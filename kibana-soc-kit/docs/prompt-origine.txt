CONTRAINTES D'ENVIRONNEMENT CONSTATÉES À L'AMORÇAGE
---------------------------------------------------
E1. www.elastic.co et docker.elastic.co sont bloqués par la politique d'egress de l'organisation
    (CONNECT tunnel failed, 403). Le README du proxy (/root/.ccr/README.md) interdit explicitement de
    contourner un refus de politique. Conséquences :
      - images : tirées depuis Docker Hub (docker.io/library/elasticsearch, docker.io/library/kibana),
        qui publie les mêmes builds officiels Elastic. La version 9.5.4 n'y est pas présente ; 9.5.3 est
        la dernière 9.5.x disponible, d'où le choix de version.
      - documentation : la doc Elastic est un logiciel libre publié sur github.com (accessible). La
        vérification documentaire s'appuie donc sur les sources officielles hébergées sur GitHub, et
        surtout sur le lab lui-même, qui reste la preuve la plus forte (CLAUDE.md : « une fonctionnalité
        absente du lab n'existe pas pour le parcours »).
E2. podman n'était pas installé : podman 4.9.3 installé depuis les dépôts Ubuntu noble. « podman kube
    play » est disponible, la fidélité à SPEC §4.1 est donc préservée.
E3. vm.max_map_count valait 65530 (< 262144 requis par Elasticsearch). Porté à 262144 par
    « sysctl -w vm.max_map_count=262144 ». Aucune commande sudo n'a été exécutée : la session est déjà
    root dans un conteneur éphémère. Sur un poste cible non root, preflight.sh affichera la commande
    sudo sans l'exécuter, conformément à CLAUDE.md.
